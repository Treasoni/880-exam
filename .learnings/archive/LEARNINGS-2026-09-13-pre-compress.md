## 2026-09-03

### 点处高阶导数存在与洛必达法则前提

**类别**：knowledge_gap
**优先级**：high
**状态**：pending
**范围**：高数 / 极限 / 880-analysis

**摘要**：只知 $f''(1)$ 存在时，不能据此在去心邻域内再次使用洛必达；应回到 $f''(1)$ 的定义完成极限。

**详情**：
- 事实：本次错题中，第一次洛必达后又对分子分母求导并写出 $f''(x)$，但题目只给出 $f''(1)$ 存在。
- 根因：把点处二阶导数存在扩大成邻域内二阶可导，遗漏了再次使用洛必达所需的邻域可导条件。
- 下次做法：一次洛必达后停止求导，将分子分母同除以 $(x-1)$；分子按 $f''(1)$ 的定义，分母分别按 $f'(1)$ 的定义和 $f''(1)$ 存在推出的 $f'$ 在 1 处连续性取极限。

## 2026-09-09

### 复用文本嵌入嵌套产物：标题层级在渲染层降级

**类别**：best_practice
**优先级**：high
**状态**：pending
**范围**：880 / wrong_book / Obsidian Markdown 排版

**摘要**：把带 `###` 标题的源文本（答案解析册原文）直接拼进 `####` 条目标题下的错题本条目会破坏 Obsidian 大纲嵌套；源文本保留原层级，渲染层把最浅标题降到条目标题之下（待复习条目 `####` → 内容 `#####`，已掌握归档 `#####` → 内容 `######`，更深标题保持相对层级、封顶 `######`）。

**详情**：
- 事实：给线代错题本 `la-c11-comprehensive-fill-004` 换新解析后，用户两次反馈"排版有问题 / 标题排版乱"——`solution` 里的 `### 考点识别`、`### 第一阶段…` 原样落在 `####` 条目标题之上，Obsidian 大纲跳级、条目被截断。
- 根因：同一 `solution` 源文本既服务答案卷（独立排版，可用 `###`），又复用到错题本条目式布局（`####` 卡片），直接拼接未做标题层级适配；曾用「去掉标题改加粗」的临时方案，仍不满足用户对真实标题层级的要求。
- 下次做法：复用源文本进嵌套型产物时，由渲染层统一做标题降级（`scripts/wrong_book.py` 的 `demote_solution_headings`），源文本不改；先登记 `.claude/rules/common/obsidian-content.md` 再同步脚本与 skill，最后重建并核验大纲层级。

## 2026-09-11

### 重建产物前先认清 `--rebuild` 的破坏性副作用

**类别**：workflow
**优先级**：high
**状态**：pending
**范围**：880 / make_paper / 卷子产物

**摘要**：`make_paper.py --rebuild` 并非无副作用重建：它清空判分卡上未判分的 `- [x]` 勾选、按 `question-index.json` 原文重渲染答案卷（未同步索引的手工解析会被回退）、并把 frontmatter `date` 重置为当天；因此重建前必须备份/提交，重建后逐项核验。

**详情**：
- 事实：替换 paper-03 第 6 题解析时执行 `--rebuild`，一次性造成 15 个判分卡勾选被清空、一8/一10 加强版解析被回退、三个文件 `date` 被改写三处副作用。
- 根因：`render_grading_card()` 无条件输出 `- [ ]`（注释误以为「判分卡无状态」）；答案卷解析事实源是索引 `solution` 而非答案卷本身；生成函数每次构建都写 `date = today`。
- 下次做法：把 `--rebuild` 当破坏性操作对待——先 `git status`/提交，重建后核验判分卡勾选与其它题解析与 `date`，被回退的用 `git checkout HEAD --` 还原；答案卷任何解析改动先写回索引 `solution` 再重建。

## 2026-09-13

### 修复发缺陷：机制要盖「源头校验 + 陈旧检测 + 流程步骤」三层

**类别**：best_practice
**优先级**：high
**状态**：pending
**范围**：880 / scripts / skills 维护

**摘要**：同族缺陷反复复发（`880-wrongbook` 公式渲染 3 次），根因不是「忘了注意」，而是修一层就收手——只在生成器写入前加校验，源头坏数据与已落盘旧产物仍能漏过。有效修复要三层同时落地：① **源头校验**（`lint_content.py::lint_source` 校验事实源索引，坏数据在源头暴露）；② **陈旧检测**（`wrong_book.py --check` 比对盘面与新渲染，旧产物不再静默留坏）；③ **流程步骤**（`SKILL.md` 固定「全部科目重生成 + 两条命令跑绿」）。

**详情**：
- 事实：本次维护 `880-wrongbook` 热点，6 条活跃记录只靠「写入前校验」一层，结果字面 `\n`/错位 `$$` 从事实源流进产物、盘面旧文件无人重写。
- 验证陈旧检测时踩过坑：先用「索引里第一条带解析的题」做负样本，改了事实源却没检出——因为该题不在错题本内，`build_wrong_lists` 不渲染它。**负样本必须选真正会被产物渲染的题**（在错题本内的题），否则「改了却没差异」是测例的问题，不是检测漏检。

**下次做法**：修一类复发缺陷，先问「源头、存量产物、日常流程」是否各有机制覆盖；缺哪层补哪层，三层都绿再归档经验库记录。
