## 2026-09-02

### obsidian-markdown：重复题号使用了过短锚点

**错误**：修复答案卷时先用 `**2.**` 定位，误命中了选择题的第 2 题，而不是解答题的第 2 题；后续断言及时阻止了错误写入。

**触发场景**：同一答案卷中多个章节都从第 1 题重新编号，直接按题号查找不唯一。

**根因**：忽略了答案卷编辑规则中“章节标题 + 完整题干”的唯一锚点要求。

**修复**：改用 `## 三、解答题`、完整题干和相邻题目边界定位后再替换。

**预防措施**：
- 修改重复题号时，先限定章节范围，再断言完整题干唯一出现。
- 写入前后检查题目数量、顺序和答案与题目相邻关系未改变。

## 2026-09-12

### 880-wrongbook：新解析使用旧式公式定界符

**错误**：新增解析使用 `\[...\]`，且一次脚本写入中出现 `\x0c`，错题本渲染异常。

**根因**：生成前没有对索引中的解析做 Obsidian 定界符和控制字符前置校验。

**修复**：统一转换为 `$$...$$`；`wrong_book.py` 新增写入前校验，并补充 skill 要求；重建后 `scripts/lint_content.py` 全部通过。

**预防措施**：今后生成器先拒绝坏解析再写文件，并固定执行 lint 回归检查。

### 880-wrongbook：两道闸门各存一份正则，行内 `\(...\)` 双双漏检

**错误**：错题本条目 `第三章 选择题 第 2 题`（qid `gs-c03-comprehensive-choice-002`）解析里的行内公式全部裸露成 `\(x\)`、`\(\Rightarrow\)`、`\(\left(\frac{x}{e}\right)^n\to0\)`，用户反馈「渲染有问题」。全本共 127 处 `\(`，涉及索引 3 道题（`gs-c01-basic-solution-003` 56 处、`gs-c02-comprehensive-choice-016` 33 处、`gs-c03-comprehensive-choice-002` 38 处）。

**触发场景**：给索引 `solution` 补写解析时用了 MathJax 式的行内 `\(...\)`。Obsidian 只渲染 `$...$` / `$$...$$`，不渲染 `\(...\)` / `\[...\]`。

**根因**：`scripts/wrong_book.py` 与 `scripts/lint_content.py` **各存了一份**只查独立式 `\[...\]` 的正则（`LEGACY_DISPLAY_RE`），两边都没有行内 `\(`/`\)` 判据。于是生成器放行、`lint_content.py` 报「全部通过」，两道闸门形同虚设——「已经有校验」反而制造了虚假信心。属于同日 `\[...\]` 那次修复的**同类复发**：上次只补了「独立式」这一种形式，没抽出共享判据。

**修复**：
- 判据收敛到单一出处：`lib880.CONTROL_CHAR_RE` / `LEGACY_INLINE_RE` / `LEGACY_DISPLAY_RE`，渲染层与 lint 共用，删掉各自的本文件副本；
- `lib880.normalize_math_delimiters()` 在渲染层把 `\(...\)` 归一为 `$...$`（源文本不改，对齐 `demote_solution_headings` 既有策略）；不安全时抛 `ValueError` 而非盲替；
- `lint_content.py` 新增行内检查（给出行号），`wrong_book.py` 写入前校验与 `make_paper.py` 答案卷渲染点均接同一函数；
- 索引 3 个 `solution` 字段归一（`git diff` 收敛为 3 行改动）；
- 重建错题本：`\(` 归 0、lint 全部通过、`git diff` 只落在对应 3 个条目。

**预防措施**：
- 同一类校验出现第二处实现时，先抽成共享函数/常量再补新形式，禁止在多个文件各写一份正则。
- 修「某种写法漏检」时，把**同族形式一次列全**（行内 `\(...\)` + 独立 `\[...\]`），不要只补用户当前撞到的那一种。
- 判别 `\[` 是否定界符要看前导反斜杠：`(?<!\\)\\[\[\]]` 跳过 LaTeX 换行 `\\[2pt]`；写断言验证时别把合法的 `\\[2pt]` 误判为缺陷。

## 2026-09-09

### 880-wrongbook：解析内 `###` 标题破坏条目标题嵌套

**错误**：更新线代错题本 `la-c11-comprehensive-fill-004` 解析后，条目内出现 `### 考点识别`、`### 第一阶段…` 等标题，直接插在 `#### 第十一章 填空题 第 4 题` 条目之上，Obsidian 大纲跳级、条目视觉截断；用户连续反馈"排版有问题 / 你看一下标题的排版啊"。

**触发场景**：给错题本条目补充/替换长解析，解析含答案卷风格的 `###` 小标题，`wrong_book.py` 直接拼接索引 JSON `solution` 源文本，未处理标题层级。

**根因**：错题本条目是 `####`（待复习）/`#####`（已掌握）容器，而源文本 `###` 是为答案卷独立排版写的；拼接时没把标题相对容器降级。第一轮临时改成"标题变加粗段落"去掉层级，仍未满足用户对真实标题嵌套排版的要求。

**修复**：
- `scripts/wrong_book.py` 新增 `demote_solution_headings()`：最浅标题降到条目级 +1，更深标题保持相对层级并封顶 `######`；待复习与已掌握归档两处渲染点统一调用。
- 把 `la-c11-comprehensive-fill-004` 的 `solution` 恢复为带 `###` 标题的原版解析（源文本不改，供答案卷保留原层级）。
- 同步更新 `.claude/rules/common/obsidian-content.md`（登记标题降级规则）与 `.claude/skills/880-wrongbook/SKILL.md`，重建两本错题本并核验大纲。

**预防措施**：
- 复用源文本进嵌套产物前，先确认渲染器是否做了标题降级；没有就先按格式修改链路补降级逻辑，再写内容。
- 生成含多级标题的长解析后，重建错题本并核验大纲层级：条目 `####` 下内容最浅为 `#####`，已掌握 `#####` 下为 `######`，全文档最深不超 `######`、不得跳级。

## 2026-09-11

### 880-paper：`--rebuild` 清空判分卡未判勾选、回退未同步索引的解析、并重置 `date`

**错误**：为替换 paper-03 填空题第 6 题解析执行 `python3 scripts/make_paper.py --rebuild paper-03` 后，产生三处非预期副作用：
- 判分卡 `判分卡-03.md` 用户已勾选的 15 个 `- [x]` 全部被清空为 `- [ ]`；
- 答案卷 `卷子-03-答案.md` 中一8、一10 两题此前手工补写、已入错题本但只存在于答案卷的「加强版解析」被回退成解析册原文；
- 卷子/答案卷/判分卡 frontmatter 的 `date`（创建日）被改写成当天 `2026-09-11`。

**触发场景**：对已有卷子的产物做格式/内容重建，走项目指定的 `--rebuild` 入口。

**根因**：
- `render_grading_card()`（`scripts/make_paper.py`）无条件输出 `- [ ]`，而 frontmatter 注释与 `rebuild_paper()` 文档字符串误判「判分卡无状态、全空勾不影响已判数据」——未判分的勾选是真实用户状态，被覆盖；
- 答案卷解析的事实源是 `workspace/question-index.json` 的 `solution` 字段，而一8/一10 的加强版解析从未写回索引，`--rebuild` 按索引原文重渲染，手工改动即丢失；
- 生成函数在每次构建时都写 `date = today`，未区分「首次创建」与「重建」。

**修复**：
- `git checkout HEAD -- workspace/papers/paper-03/判分卡-03.md workspace/papers/paper-03/卷子-03.md` 还原勾选与未变动的卷子；
- 从 `git show HEAD:…卷子-03-答案.md` 程序化提取一8/一10 的加强版解析，写回 `workspace/question-index.json` 的 `solution` 字段，使事实源与产物一致后再重建，diff 收敛到「frontmatter + 第 6 题」；
- 手工把答案卷 `date` 还原为 `2026-09-03`（保留 `updated: 2026-09-11`）。

**预防措施**：
- 执行 `--rebuild` 前先 `git status`/`git stash` 或确认目标文件已提交；重建后必须逐项核验：判分卡勾选、答案卷其它题解析、三个文件的 `date`。
- 答案卷任何解析改动都要先写入 `workspace/question-index.json` 的 `solution`（事实源），再 `--rebuild`，禁止只改答案卷。
- 修 `make_paper.py` 前，重建前先备份受影响卷目录，重建后 `git diff` 确认改动范围符合预期。
