### 一次性脚本：python -c 漏导入 Path 导致 NameError

**错误**：重建 paper-01 答案卷的一次性 `python -c` 片段第 19 行 `NameError: name 'Path' is not defined`，脚本跑挂一次。

**触发场景**：用 `python -c` 内联运行多步脚本时。

**根因**：内联片段顶部忘了 `from pathlib import Path`，直接用了 `Path()`。

**修复**：
- 补上 `from pathlib import Path` 后重跑成功，答案卷按预期重建。

**预防措施**：
- 用 `python -c` 跑一次性脚本前，先把所有 import 在开头写全再执行；步骤较多时写成临时 `.py` 文件再运行，避免内联片段漏导入。

---

### 判分卡解析：QHEAD_RE 粗体题头正则写错括号内句点

**错误**：`parse_grading_card()` 新格式题头正则 `^\*\*(\d+)\*\*\.\s*答案` 匹配 `**1.** 答案：D` 失败，新格式判分卡解析返回空 grading。

**触发场景**：为判分卡任务清单格式写 `**N.** 答案：…` 题头识别正则时。

**根因**：`**1.**` 中数字后的 `.` 位于粗体闭合标记内侧（`**` + `1.` + `**`），正则却写成 `\*\*(\d+)\*\*\.`（误以为 `.` 在 `**` 之后）。

**修复**：
- 改为 `^\*\*(\d+)\.\*\*\s*答案`，自测单勾/多勾/全空/旧格式全部通过。

**预防措施**：
- 解析 `**text.**` 这类粗体时，闭合 `**` 在句点之后；
- 给解析器写单勾/多勾/全空/旧格式的单元自测再落地。

### 校验正则：`\d` 匹配不到两位数行号（`一10`）误报少一格

**错误**：用正则 `\| (?:一|二|三)\d \|` 统计判分表勾选行，结果 19 格而非 20 格，一度以为判分卡漏了状态。

**触发场景**：校验判分卡是否每题都勾了状态，用正则扫描 Markdown 表格行时。

**根因**：`\d` 只匹配单个数字；`| 一10 |` 是两位数，`三\d ` 无法匹配，导致该行被漏数。实为误报，判分卡本身无错。

**修复**：
- 改用 `sed` 直接读取判分表确认全部 20 格正确，实数据无问题。

**预防措施**：
- 正则匹配数字一律写 `\d+` 而非 `\d`；
- 对「计数/校验类」结论，先用 `sed`/`grep` 直接看原始文件确认，再下结论，避免仅凭正则扫描误判。
